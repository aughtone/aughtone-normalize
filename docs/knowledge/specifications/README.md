# Specifications

How things ARE: the suite's module structure and contracts, and the engineering standards the code is held to. These are updated in place — a specification describes the present, so it is corrected rather than superseded, and it should never disagree with the code.

**These are normative.** Code that contradicts a specification here is a bug in the code, not a document that has gone stale — correct the code, or change the specification deliberately and say why in an [ADR](../decisions/README.md). [AGENTS.md](../../../AGENTS.md) binds agents to this section by name, which is what makes that enforceable; the section carries the obligation, not any prefix on a filename.

**Not here:** why a choice was made over its alternatives ([Architecture Decision Records](../decisions/README.md)), or a question still being worked out ([Research](../research/README.md)). If a document is arguing rather than describing, it belongs in one of those.
