# Architecture Decision Records

One hard-to-reverse choice per record: the forces that applied, the option taken, and what was rejected and why. Written when the decision is made rather than afterwards.

**A record is corrected when it is wrong.** A decision stands only while it is right: when it rests on a fact that turns out to be mistaken, or names something that has since been renamed, fix the record so it says the true thing. Git and the wiki keep every earlier version, which is where the history lives — a record left saying something false is not history, it is a trap for the next reader. Note the correction in the header line when the substance changes; a rename or a typo needs no note.

**A decision that is reversed outright still gets a new record.** Changing direction is itself a decision, with its own forces and its own rejected options, and it supersedes rather than overwrites.

Anything that changes a published canonical form belongs here, because that class of change cannot be undone: consumers have already derived and stored tokens from the old bytes.

**Not here:** how something currently works (that is [Specifications](../specifications/README.md)), or an investigation that has not settled on a choice yet (that is [Research](../research/README.md)). A recommendation only becomes a decision when someone commits to it.
